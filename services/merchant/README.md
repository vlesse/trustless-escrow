# 自动发货程序（卖家自己运行）

卖点卡、激活码这类数字商品的卖家用它：**有人下单，它自动把卡密加密后发给买家**，不用你盯着。

## 它做什么

每 20 秒检查一次：

1. **发货**：找到已付款、还没发货的订单，从这个商品的卡密文件里取一张，用这个买家的取货钥匙加密，写进这一单的合约里。只有这个买家能解开，平台和任何人都看不到。
2. **同步库存**：链上的库存数 = 卡密文件里还没发出去的张数。卡密用完，商品自动停售，不会卖出发不了货的单。
3. **补押金**：订单结束后押金会退回你的钱包，程序把它存回押金账户，保证随时接得了新单。

## 怎么用

```bash
npm install
cp .env.example .env      # 然后打开 .env 填上你的钱包私钥和店铺合约地址
mkdir codes
```

每个商品一个卡密文件，文件名是商品编号（在 Telegram 里 `/shop` 能看到）：

```
codes/1.txt
```

一行一张卡密，`#` 开头的是注释：

```
# 王者荣耀 100 元，10 月那批
WZRY-100-8842-XK19-ZZ07
WZRY-100-5531-QP20-MM41
```

启动：

```bash
npm start
```

补货：直接往文件里加行，程序下一轮会自动把链上库存调上去、重新开卖。

## 必须知道的三件事

**同一张卡密绝不会发两次。** 程序在发交易**之前**，先把「这一单分到哪张卡密」记进 `.merchant-state.json`。中途断电重启，它还是用同一张给同一单。所以：

- **`.merchant-state.json` 要备份。** 丢了它，程序就不知道哪些卡密已经发出去了。
- **不要从卡密文件里删掉已经发出去的卡密。** 删了没关系（程序按账本判断），但留着方便你对账。
- **不要同时在两台机器上跑。** 两个程序各有各的账本，会把同一张卡密发给两个人。

**钱包私钥放在这台机器上。** 它就是收货款的钱包。它碰不到任何买家的钱（买家的钱锁在每一单自己的合约里），但你的收入会进这个钱包：**定期把收入转到冷钱包**，这里只留补押金用的零钱。

**超过交付期就发不了了。** 合约不接受过期的发货，买家可以取回全部货款。所以程序要一直开着；它停了多久，这段时间里的订单就可能超时。

## 发不出货的时候

程序会在日志里说原因：

| 日志 | 意思 | 怎么办 |
|---|---|---|
| 卡密发完了 | 这个商品没货了 | 往卡密文件里补 |
| 买家没留取货钥匙 | 买家不是从下单页买的 | 你手动联系买家发货 |
| 已经过了交付期 | 程序停太久了 | 这一单买家可以退款，保持程序常开 |
| 没有卡密文件 | 文件名和商品编号对不上 | 检查 `codes/商品编号.txt` |

## 吵架的时候

卡密是加密后写在链上的，交没交、交的是哪一张，链上永久可查。买家说卡密无效，你可以把这一单用的临时密钥公开，任何人都能解开核对当时发的到底是什么。
