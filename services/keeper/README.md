# keeper

推动协议里那些**任何人都可以做、但没人会主动做**的步骤。

## 为什么需要它

陪审团流程里有四步是无需许可的：抽签 → 开揭示 → 计票 → 结案。乐观层还有两步（超时升级、默认裁决生效）。托管合约还有一步（验收期届满结算）。

**无需许可不等于会有人做。** 这些步骤要发交易、要付 gas、要有人盯着时间窗口。当事人未必在线，陪审员未必愿意替别人垫 gas。

没有 keeper 的后果很具体：争议一直卡在某一阶段，直到十天的兜底超时触发，然后**以拒裁收场，中性拆分**——该赢的人拿不到该拿的，而机制本身明明已经判出了结果。

## 它的钥匙偷走一文不值

这是设计上最重要的一点。keeper 能做的每一件事，合约上**任何人**都能做：

- 它碰不到任何人的托管资金
- 它没有任何 `onlyAdmin` 权限
- 它不质押、不会被罚没

所以它可以热放在服务器上。但**不要和另外两把钥匙共用**：

| 钥匙 | 能做什么 | 丢了会怎样 |
|---|---|---|
| keeper | 推进无需许可的步骤 | 别人替你推，没有损失 |
| 提案人 | 出具默认裁决并质押 | 保证金被罚没 |
| 管理员 | 停新单、换仲裁层配置 | 新单被恶意卡死 |

## 跑起来

```bash
npm i
cp .env.example .env    # 填 RPC、工厂地址、keeper 私钥
npm run dry-run         # 先干跑，看它打算推什么
npm start               # 确认无误后再真的上链
npm run once            # 跑一轮就退出，适合放进 cron
```

启动时会拿链上的窗口常量核对本地写死的那几个，不一致直接退出——推早了白白 revert，推晚了资金多压几天，两种都不报错。

## revert 不等于失败

每一步在发交易之前先 `staticCall` 试一次。跑不通就当作「现在还轮不到我」安静跳过，**不计入失败次数**。

这不是容错，是语义：这些方法本来就开放给所有人，被当事人、陪审员或另一个 keeper 抢先推掉是完全正常的结果。分不清这两件事的话，日志会被正常现象淹没，真正的故障反而看不见。

只有交易真的发出去又失败了才计数，连续失败到上限就放弃那个目标——不对着一个永远 revert 的调用无限烧 gas。

## 判断逻辑是纯函数

`src/tasks.js` 不碰链，只接受状态、返回「该推哪一步」。这些条件写错不会报错，只会让 keeper 安静地什么都不做——没有运行时信号的东西，必须在测试里钉住。

一条要紧的口径：**能走正常流程就绝不走兜底**。`timeoutCase` 会让案件以拒裁结束，那是把一个本来能判出输赢的案子改成中性拆分，只在正常路径确实走不动时才用。
