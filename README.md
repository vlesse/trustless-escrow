# Trustless Escrow

非托管的点对点担保交易协议。资金锁在每笔交易独立的智能合约里，运营者在任何时刻都无法挪用。

> [!WARNING]
> **这些合约没有经过第三方安全审计,现在不要用它承载真实资金。**
> 代码可复现编译、测试覆盖到每一条结算路径与兜底路径,但那替代不了独立审计。
> 如果你打算部署它,请先自己审,或者找人审。出了事没有人能替你兜底 —— 这正是「非托管」的另一面。

## 为什么是这个结构

担保平台跑路不是技术问题，是商业模式问题：沉淀资金的规模远大于手续费收入的折现值，到某个临界点，跑路成为运营者的理性选择。

所以本协议的全部设计围绕一件事——**让运营者在任何时刻都拿不到沉淀资金**。跑路无利可图，跑路就不会发生。

## 信任模型

这是本项目最重要的一节。请在使用前逐条自行验证。

### 运营者**不能**做的事（由代码强制，非承诺）

| 事项 | 强制手段 |
|---|---|
| 挪用托管中的资金 | `Escrow` 无 owner / admin 角色，无 `pause`、无 `emergencyWithdraw`。资金只有 4 个出口：买家、卖家、仲裁方（仅争议成本）、手续费金库 |
| 收取超过 1% 的手续费 | `Escrow.MAX_FEE_BPS = 100` 写死在实现合约里，工厂与管理员都无法突破 |
| 修改已存在交易的条款 | 所有参数在 `initialize` 时逐笔快照，此后永不可变。工厂事后改默认值，对已创建的交易零影响（有测试覆盖） |
| 更换托管逻辑 | `EscrowFactory.implementation` 是 `immutable`，无代理、无升级路径 |
| 改走手续费收款地址 | `FeeVault.beneficiary` 是 `immutable`。部署后永久固定，私钥泄露也改不了 |
| 靠不归集手续费来模糊账目 | `FeeVault.sweep()` 无权限控制，任何人都能推动归集 |
| 在争议交易上收费 | 争议、取消、超时路径的手续费恒为 0（有测试覆盖） |
| 卷走在途的挑战保证金 | `OptimisticArbitrator.sweep()` 只能归集 `余额 − lockedBonds`，由合约记账强制 |
| 动用陪审员的质押 | `StakedJury` 没有任何管理员提取函数。质押只能由陪审员本人 `unstake`，或因错判被罚没给同案的其他陪审员 |
| 操纵陪审团人选 | 抽选种子 = 区块哈希 ⊕ VRF 输出，两者都在争议创建之后才产生；且按质押加权，无法靠拆号提高中选率 |
| 靠换一个自己写的「随机数」合约来指定陪审员 | 随机数来源只是**混入**种子而非替换种子，且逐案快照。换来源的影响上限被压到「和出块者研磨区块哈希差不多」 |
| 无声替换仲裁人 | 配置变更需 `proposeConfig` → 公示 7 天 → `applyConfig`，全程上链可见 |
| 罚没用户的身份押金 | `IdentityBond` 没有任何罚没函数，出金路径只有一条：本人 `withdraw()`，且需公示 14 天。部署者也拿不走 |
| 删改或压制信誉记录 | `Reputation` 只有 `record` / `recordMany` 两个写入函数，没有删除入口；记录是无许可推送的，受害者可以自己把骗子的败诉记录推上链 |

### 运营者**能**做的事

- 为**未来的新交易**调整默认仲裁人、费率（1% 封顶）、手续费金库——须经 7 天时间锁公示
- 更换 AI 提案人地址
- 归集已赚取的手续费与仲裁服务费

管理员权限可以通过 `factory.transferAdmin(address(0))` 永久放弃，此后协议参数完全冻结。

### 你仍然需要信任的部分

诚实地讲清楚边界：

1. **陪审团的集体判断**。链上合约无法验证链下履约（oracle problem）——一个数字商品到底交付了没有，链本身永远不知道。最终必须有人做判断。本协议能做的是**把资金控制权从判断者手里拿掉**，只留给它投票权。但 Schelling point 在证据模糊或存在大额贿赂时会失效，这是该类机制的固有边界。
2. **随机数质量**。种子混合了区块哈希与 Chainlink VRF 的输出。未配置 VRF 时退化为纯 `blockhash`，出块者有有限的操纵能力；配置之后，把随机性降级回这个水平需要持续审查 VRF 回调满 2 小时。**没有被完全消除。**
3. **上诉会拖时间，但拖延现在要赔钱**。一轮陪审团判错了，任何人都可以自费把案件升到更大的一轮（最多三轮）。上诉费之外另收一笔按案值 2% 计的**拖延押金**：推翻原判原额退还（纠错免费），维持原判则赔给终局裁决判给的那一方。所以拖延仍然做得到，但不再是免费的——**代价是赔给被你拖住的人**，而不是像从前那样进陪审员口袋。
4. **陪审团的经济承载力是有限的，而且可以算出来**。`jury.juryCoverage()` 给出「买通过半席位至少要覆盖多少钱」。案值超过它，买裁决就比认输划算。合约**不拿这个数拦人**——commit-reveal 让贿赂无法执行（陪审员收了钱照样可以诚实投票，行贿者事后毫无办法），所以真实的安全倍数比这个下界高得多，但高多少没人知道，把一个拍脑袋的系数写进共识规则是错的。硬闸开在另一处：`factory.maxDealValue(token)` 是运营方设的单笔上限，拦在**入金之前**。
5. **入金前自行核对**。新交易使用工厂当前的默认仲裁人。入金前请检查 `deal.arbitrator()` 是不是你认可的那个。
6. **合约本身未经第三方审计**。代码可复现编译（`npm i && npm run build`），做过一轮自审（Slither + 人工分拣，记录见 [docs/SELF-AUDIT.md](docs/SELF-AUDIT.md)，修掉了一个真实的重入问题），但**自审替代不了第三方审计**。静态分析看不懂博弈，而这个协议最可能出事的地方恰恰在那里。

## 架构

```
EscrowFactory ──creates──> Escrow (每笔交易一个实例，EIP-1167 克隆)
     │                        │
     │                        ├─ 资金：货款 + 买家保证金 + 卖家保证金
     │                        └─ 争议时 ──> OptimisticArbitrator
     │                                          │
     └─ 7 天时间锁的配置                        ├─ AI 提案 + 48h 挑战窗口
                                                │   无人挑战 → 直接生效（95% 的案子）
                                                └─ 被挑战 → StakedJury
                                                              │
                                                              ├─ 按质押加权随机抽选
                                                              │   种子 = 区块哈希 + VRF（混合，非替换）
                                                              ├─ commit-reveal 投票
                                                              └─ 少数派 / 装死者罚没
FeeVault    ── 手续费唯一归集地，受益地址 immutable
Reputation  ── 托管层的只读旁观者，拉取式记录，无删除入口
IdentityBond ── 身份押金，无罚没、无 owner，撤回需公示 14 天
```

### 争议层为什么要两级

「自动化机器人判案」的根本缺陷是：机器人是单点，谁控制它谁就控制所有资金流向。而且 LLM 判决不可复现、可被 prompt injection 攻击。

本协议把机器人降级为**提案人**：

- AI 提出默认裁决，并**质押保证金**——它对自己的结论有真实风险敞口
- 48 小时内，**任何人**（不限当事双方）都可质押等额保证金挑战
- 无人挑战 → 生效。明显的案子走这条路，快且几乎零成本
- 被挑战 → 升级终局仲裁，AI 的意见不再有任何效力
- 错的一方保证金罚没给对方

纠错权是开放的，所以机器人不再是单点。AI 掉线也不会卡死：超过 72 小时未提案，任何人可直接升级；争议超过 45 天无裁决，任何人可触发中性拆分取回资金。

### 终局仲裁：质押陪审团

`StakedJury` 是整个协议里唯一真正做「判断」的地方。四个机制撑起它：

**按质押量加权抽选。** 如果等概率抽选，把 10 份质押拆成 10 个账号就能拿到 10 倍中选概率——这是对陪审团的女巫攻击。加权抽选让影响力与抵押的钱严格挂钩，拆号不产生任何收益。用 Fenwick 树实现。

> 实现上有个容易踩的坑：Fenwick 节点 `i` 覆盖区间 `(i - lowbit(i), i]`。如果树的上界随陪审员人数增长，早期写入的 delta 不会传播到「当时还不存在、后来才出现」的祖先节点，前缀和会永久错乱。所以容量固定在上界（用 mapping 存储，未触碰的槽位零成本）。

**commit-reveal 两阶段投票。** 直接明文投票的话，后投的人能看到先投的结果，会产生跟风，投票不再独立，多数决的纠错能力失效；也让贿选变得可验证因而更容易。承诺哈希里必须同时包含 salt（否则只有两个取值的承诺可被暴力枚举）和投票人地址（否则可以直接抄别人的承诺）。

**一致者得赏，少数派与装死者罚没。** 这是 Schelling point 博弈：当你不知道别人会怎么投，最优策略是投「你认为大多数诚实人会认为正确的那个答案」。证据清晰时，这个点就是真相。不揭示必须同样被罚没，否则陪审员会只在有利时才揭示。

抽选是**放回抽样**——同一个人可能占据多个席位，多锁一份质押、多一票、也多一份罚没风险。

**裁决出来之后还有一个上诉窗口。** 见下一节。

### 上诉：陪审团自己判错了怎么办

一裁终局的问题不在于陪审团不可靠，而在于**它出错时没有任何补救路径**，而代价全部由被误判的一方承担。

所以一轮结束后，裁决**不会立刻投递给托管合约**，而是先开 48 小时的上诉窗口。任何人都可以自费把案件升到下一轮，最多三轮：

| 轮次 | 席位 | 价钱（以第一轮服务费为基准） |
|---|---|---|
| 初审 | 3 | 1× |
| 第一次上诉 | 7 | 7/3× |
| 第二次上诉 | 15 | 5× |

价钱按**席位等价**计算——每个陪审员拿到的报酬与第一轮一样多。所以它随陪审团规模涨，而不是随货值涨；后者会让小额交易的当事人上诉不起，而陪审员的工作量并没有变化。

**另收一笔拖延押金。** 上诉费是付给陪审员的工钱，它惩罚不了拖延——那笔钱进的是陪审员口袋，被多锁一个轮次的那一方一分钱补偿都没有。所以上诉时另付案值的 2%：

| 上诉结果 | 拖延押金去向 |
|---|---|
| 推翻了原判 | 原额退还上诉人。**纠错本身不该收费**，否则没人愿意纠错 |
| 维持原判 | 赔给终局裁决判给的那一方。他的钱因为这次上诉被多锁了一个轮次 |
| 终局是拒裁 | 退还上诉人。没有「被拖延的赢家」可赔 |

判定看的是「这一轮有没有真的改变结论」，而且要跟**本轮之前最后一个真正出了结论的轮次**比——不能直接看上一轮，上一轮可能是集体沉默的 0，那不是一个结论。这和乐观层的 `challenge` 完全同构：全协议一以贯之的「谁错谁赔给对方」。

几个刻意的选择：

**上诉不是免费的重摇。** 每一轮都比上一轮大一倍多。如果上一轮是对的，更大的一轮只会更对——重摇并不提高翻盘概率，却要付成倍的钱。只有上一轮确实处在边缘，上诉才划算。

**每一轮只对自己那一轮负责。** 另一种常见做法是等案件终局后，回过头把所有轮次统一按终局裁决判定对错。它听起来更自洽（「真相只有一个」），但打开了一个很难堵的攻击：一个有钱的攻击者**逐级上诉到最后一轮并买通那一轮**，就能追溯罚没前面每一轮所有诚实陪审员的质押——他的成本被上诉费封顶，诚实陪审员的损失却没有上限。代价是初审被推翻时，初审的多数派仍然拿到了报酬；但上诉制度的前提本来就是「前一轮可能是错的」，付钱给初审并不等于宣布初审是对的。

**沉默的上诉轮不会变成免费的平局。** 终局裁决取的是**最后一个真正出了结论的轮次**，而不是简单地取最后一轮。上诉轮全员装死时它的 ruling 是 0，若直接拿这个 0 当终局，托管合约会做中性拆分——于是就有了一条现成的攻击：眼看要输的人先上诉，再让那一轮集体沉默，把一场必输买成五五开，而买通一群人「不投票」比买通他们「改投」便宜得多。退回上一轮的裁决之后，沉默的上诉轮唯一的效果是白花一次时间。

**上诉的价钱在受理时就快照好了。** 否则管理员多一个开关：看到一个不想被推翻的裁决，把第一轮价钱调高到当事人付不起为止。

**上一轮的陪审员不被排除在重抽之外。** 排除他们听起来更公平，实际上会给攻击者一个廉价的操控手柄：先让自己的地址中选并故意乱投，就能把他们从后续更大的一轮里踢出去。

**轮数上限是被时间预算卡死的，不是拍脑袋。** 每轮占 5 天（提交 3 天 + 揭示 2 天），每个上诉窗口再占 2 天，加上乐观层的 5 天，最坏约 29 天。托管合约的仲裁方失联保护定在 45 天——必须大于这条式子，否则兜底机制会把一个正常推进的案件提前打成平局，那比没有兜底更糟。缩短任何一个窗口之前，先重算这条式子。

**投递失败不能把陪审员拖下水。** 托管合约在失联保护触发后就不再接受裁决，`rule` 会 revert。如果结案时不兜住这个 revert，整个结案会回滚，案件永远停在非终态，**所有被抽中的陪审员的质押就此永久锁死**。所以投递用 try/catch，失败的代价被限制在「本案拿不到服务费」。同理，结案时就解锁全部质押，而不是等陪审员自己来领报酬——一笔几十块的服务费，不该以锁死本金为代价。

### 抽选的随机数：混合，而不是替换

接一家预言机很容易变成给协议塞一个新的单点。这里有两条硬约束：

**一、它停摆时资金不能卡住。** 所以随机数请求失败不会阻断争议创建（降级为纯 blockhash 并留下事件），回调迟迟不来则等满 2 小时后照样可以抽选。一个坏掉的预言机只能降低随机性，不能剥夺当事人提起争议的权利。

**二、它作恶时不能比不用它更糟。** 这一条才是关键。随机数来源是管理员可配置的——如果直接拿它的输出当种子，管理员就获得了一项协议里别处都不存在的权力：装一个自己写的合约，从而**指定陪审员**。那比 blockhash 糟得多。

所以种子是 `keccak256(区块哈希, 随机数, 案件ID)`——**混入，不是替换**。于是最坏情况有了下界：

| 情况 | 结果 |
|---|---|
| 来源返回攻击者指定的值 | 他还得同时操纵区块哈希 |
| 来源停摆 / 被审查 | 超时后退回纯 blockhash |
| 来源诚实 | 出块者即便研磨区块哈希也无法预知 VRF 输出 |

三种都不比「完全不接预言机」更差，而正常情况明显更好。

顺序也不构成新的攻击面：VRF 先于抽选区块返回时，该区块的出块者知道 VRF 值并可尝试研磨区块哈希——这正是今天的水平；VRF 后返回时，预言机知道区块哈希，但 VRF 的输出是可验证的，它只能扣住不发（→ 超时 → 退回 blockhash），不能挑一个自己想要的值。

来源合约按「可能是恶意的」处理：所有调用限 gas，revert / 烧 gas / 返回畸形数据一律当作「尚未就绪」。并且**来源是逐案快照的**，管理员没法在看到一个不想输的案子之后再去换。

`ChainlinkVRFSource` 自己没有 owner，结果一旦产生不可更改——允许覆写等于允许在看到抽选结果之后重摇，那比没有随机数更糟。

### 保证金与罚没

双边保证金是防作恶的核心。**违约方的保证金罚没给对方**，不是原路退回——退回等于零成本作恶，攻击者可以无限次尝试，期望收益为正。

买卖双方对称：卖家不发货罚没，买家谎称没收到同样罚没。否则恶意申诉会变成一个免费的攻击面。

### 证据

链上只记录证据的 URI 与哈希。**截图在今天已经基本不能作为证据**——AI 伪造成本接近零。仲裁层应按可验证性分级加权：

- 强证据：链上 txid、支付网关签名回调、物流商 API 可回查单号、zkTLS 类可验证网页快照
- 弱证据：截图、口述

`termsHash` 记录链下条款全文的哈希，确保争议时「当初约定的是什么」无法被任何一方事后篡改。

- 上诉轮：裁决在窗口结束前不得落地、上诉可推翻初审、**初审多数派不会被上诉轮追溯罚没**、轮与轮的席位互不串台
- **全链路集成**：AI 误判 → 被挑战 → 陪审团推翻 → 裁决一路传导回托管合约，三层的钱都对得上
- 每一层的兜底路径：仲裁方失联、AI 下线、陪审团卡死、blockhash 超出回溯范围、**上层拒收裁决时陪审员的本金仍能取回**
- 重入防护：带转账回调的代币无法在上诉时多吃一轮（该用例在修复前会失败，已验证）
- 信誉层的抗伪造：拒绝非本工厂的合约、拒绝零成本的空交易、刷单的形状（笔数涨而对手方数不涨）
- 随机数来源作恶的全部姿势：返回攻击者指定值、整个 revert、烧光 gas、请求成功但永不回调——每一种都不能让争议卡住，也都不能让它指定陪审员

## 部署

```bash
FEE_BENEFICIARY=0x... PROPOSER=0x... SETTLEMENT_TOKEN=0x... FEE_BPS=50 \
  npx hardhat run scripts/deploy.cjs --network <net>
```

一次部署全部七个合约并完成费率配置（`SKIP_REPUTATION=1` 可跳过信誉层；填了 `VRF_COORDINATOR` 会额外部署并接上 VRF 来源）。可选参数见 `scripts/deploy.cjs` 顶部注释。

两处值得注意的地方：

- 工厂与仲裁层之间存在循环依赖（工厂构造需要仲裁人地址，仲裁层构造需要工厂地址做准入校验）。脚本用 **nonce 预测**填对地址，而不是「先用占位地址、上线后再改」——后者会逼迫首次配置绕过 7 天时间锁，等于在创世时刻给自己开一个后门。
- 费用配置必须满足 `OPT_COST >= JURY_COST`，否则乐观层在升级争议时付不起陪审团的报酬。合约会在受理争议时拦住这种错配（有测试覆盖），但最好别等到那时候才发现。

部署后**陪审员池为空，争议无法受理**——上线前必须先招募到陪审员质押。

## Telegram 前端

用户界面在 [`services/bot/`](services/bot/)，详见该目录的 README。

压倒一切的设计约束是**机器人不持有私钥** —— 不是承诺，而是代码里根本没有接收私钥的路径。机器人只读链、编码 calldata、排版消息；签名全部在用户自己的钱包里完成。所以机器人被攻破、关停或封禁，用户的钱都不受影响：每笔操作除签名链接外都同时给出原始 `to` + `calldata`，任何钱包都能手工执行。

另外两处：钱包绑定要求签名证明控制权（挑战文本绑定 Telegram 用户 ID + 一次性 nonce，防冒用防重放）；主动检测用户粘贴的私钥与助记词并告警，该消息不进入任何存储，日志也永不打印消息内容。

还带链上事件推送与到期提醒。**到期提醒不是锦上添花**——验收期届满买家还没动作，货款就自动放给卖家了，所以提醒只发给「不作为会吃亏」的那一方并说清后果。推送等 5 个确认再发：重组后一条已推送的「对方已入金」会变成假消息，而用户可能已经据此发了货。

## 信誉层

[`contracts/reputation/`](contracts/reputation/) —— 两个合约，都是可选的，托管层完全不依赖它们。

**它是托管层的只读旁观者。** `Escrow` 不知道它存在，也从不调用它。记录是拉取式的：交易结束后任何人调用 `Reputation.record(deal)`，合约自己去读那笔交易的终局状态。反过来做（结算时推送）意味着在持有资金的合约的结算路径上插一个外部调用——那个调用一旦 revert 或耗尽 gas，结算就失败，用户的钱锁死在里面。**一个统计功能不值得换来这种风险。**

无许可推送还有一个直接后果：**骗子无法压制自己的败诉记录**。他不能拒绝调用（调用不需要他），也不能删除（合约没有删除函数）。

**身份押金不是罚金。** `IdentityBond` 没有罚没功能，没有 owner，唯一出金路径是本人 `withdraw()` 且需公示 14 天。它买的不是威慑，是**年龄**——钱可以瞬间凑齐，年龄不行。一个刚创建的地址无论押多少，都装不出两年前就在这里。所以只能整笔撤回：能部分撤回的话，一个身份就能保着「两年年龄」把押金抽到接近零。

**合约只记事实，不打分。** 评分是政策，政策会随骗术演化而需要修改，把它写进一个永不可变的合约是自找麻烦。

**展示的是缺口，不是星级。** 机器人算的是针对这一笔交易的一个数：

```
机制缺口 = 货款 − 对方在这笔交易里的保证金
```

缺口 ≤ 0 时结论是绿色，**且与对方是谁无关**——罚没大于收益，作恶在数学上不划算，你不需要判断一个陌生人可不可信。这是最强的那种保障。只有缺口 > 0 时信誉才开始说话，而那时页面给出的建议是**「把对方的保证金提到不低于货款」，而不是「相信这个人」**。

刷单的形状是可见的：笔数 40 而对手方 2 个，就是两个地址在自己跟自己刷。并且刷出来的每一笔都要烧掉真实手续费进入不可变金库——所以「伪造这份记录至少要花多少钱」有一个硬下界。

代价要讲清楚：**信誉与匿名是直接冲突的**，有记录就意味着你的交易全部被链接到同一个地址。所以它是自愿的，不想留记录就每次换地址，代价是对手方凭什么信你。协议不强制任何一边，也不因为你没有记录就拒绝你交易。

## 签名页

[`services/signing-page/`](services/signing-page/) —— 纯静态、无后端、依赖 vendor 不走 CDN。

它把机器人编码好的 calldata 翻译成人话（"确认收货并放款给卖家 · 不可撤销"），并在链上独立验证目标确实是工厂登记的托管合约。**解不出来或验不过就阻止签名**——一个只会说"请签名"的页面是在训练用户盲签，而盲签正是钓鱼得手的前提。

交易内容走 URL 的 `#` 片段，不会发给服务器，所以托管方也看不到任何人在签什么。

身份押金相关的调用同样要通过验证：目标必须等于本地 config 里配置的押金合约地址——**没配置就拒绝放行**，因为无法验证目标时，不放行才是正确的默认。

这个页面不是必需的：机器人每条操作消息都同时给出原始 `to` + `calldata`，页面挂了用户照样能用任何钱包完成操作。

## AI 提案人服务

链下机器人在 [`services/proposer/`](services/proposer/)，详见该目录的 README。

它不是法官，是提案人：裁决有 48 小时挑战窗口，且它为每个裁决质押保证金。三条核心设计——

- **提示注入当作首要威胁处理**：系统提示词完全静态，证据包在每次请求随机 nonce 的标签里，模型无任何工具。检出的注入企图不过滤而是标注，作为对该方不利的证据。
- **验证由服务做，不是由模型做**：条款真伪靠 keccak256 比对链上 `termsHash`（哈希对上即为真本，与谁提交无关），txid 一律实际查链。其余一律标为 unverified，且 unverified 不能压倒 verified。
- **不确定就弃权**：不走合约的中性拆分，而是完全不提案、让案件升级给陪审团。「我判不了」不等于「双方都没错」。
